# TakımBul v9.1 — Professional Home, Reliable Ads & Isolated Admin

V9.1, v9 Matchday sürümünü değiştirmeden dört üretim sorununu kapatır: ana sayfadaki ham/0 ağırlıklı metrik sunumu, konum hedefli reklam teslimatı, zorunlu e-posta doğrulaması ve yönetici hesabının normal kullanıcı kimliğiyle karışması.

## 1. Tamamen ayrı yönetici hesabı

- Yönetici kimlikleri artık `users` tablosunda değil, ayrı `admins` tablosundadır.
- Yönetici girişi: `/admin/giris`.
- Normal kullanıcı girişi: `/giris`.
- Yönetici oturumu açıldığında varsa normal kullanıcı oturumu kapatılır.
- Normal kullanıcı oturumu açıldığında varsa yönetici oturumu kapatılır.
- Yönetici hesabı kariyer profili, takım üyeliği, mesaj, maç veya oyuncu istatistiği üretmez.
- Fresh kurulumda `veribayt` yalnızca `admins` tablosuna seed edilir.
- Eski v8.1/v9 kurulumundaki yönetici kullanıcı satırı, FK geçmişini bozmamak için login olamayan `deleted` tombstone kaydına dönüştürülür.
- Admin e-posta/kullanıcı adı normal üyeler tarafından kullanılamaz.

Yönetici parolası kaynak kodda düz metin tutulmaz. `schema.sql` ve migration yalnızca one-way `password_hash` içerir. Parolayı sonradan değiştirmek için:

```bash
TAKIMBUL_ADMIN_PASSWORD='YENI_GUCLU_SIFRE' php scripts/admin-bootstrap.php
```

## 2. Ana sayfa profesyonel metrik sunumu

Misafir ana sayfasındaki büyük 0 sayaçları kaldırıldı. Yerine koyu, kompakt `TakımBul Ağı` canlı durum paneli geldi.

- Gerçek DB verisi varsa sayı gösterilir.
- Veri oluşmamışsa sahte sayı veya büyük `0` yerine `—` gösterilir.
- Hero metni ve proof satırı daha ürün odaklı hale getirildi.
- Giriş yapan kullanıcıda sezon, güven ve kariyer metrikleri veri yokken `— / Henüz puanlanmadı` gibi doğal boş durumlara düşer.

## 3. Reklam teslimat düzeltmesi

Eski sorgu, il/ilçe eşleşmesini MySQL `LOWER()` üzerinden yaptığı için `I / İ / ı` gibi Türkçe karakterlerde uygun reklamı SQL aşamasında yanlışlıkla eleyebiliyordu.

V9.1'de:

- SQL yalnızca aktiflik, slot, tarih ve cihaz için aday kampanyaları getirir.
- İl/ilçe eşleşmesi PHP tarafındaki Türkçe-normalize edilmiş karşılaştırmayla yapılır.
- Uygun yerel reklamlar genel reklamlardan önce tercih edilir.
- Aynı hedef seviyesinde daha az gösterilmiş reklam döndürülerek rotasyon korunur.
- Uygun yerel reklam yoksa genel Türkiye reklamı fallback olarak gösterilir.
- Admin Reklam Merkezi'nde cihaz + il + ilçe girerek teslimatı manuel simüle edebileceğin test alanı vardır.

## 4. E-posta doğrulaması geçici olarak kapalı

- `require_email_verification` site ayarı varsayılan `0`.
- Yeni üye kayıt sonrasında doğrulama maili beklemeden oturum açabilir.
- Girişte doğrulama engeli yoktur.
- Doğrulama yeniden gönder bağlantısı yalnızca admin ayarı tekrar açarsa görünür.
- Şifre sıfırlama e-postası çalışmaya devam eder.
- `/admin/ayarlar` içinden **E-posta doğrulaması zorunlu** anahtarıyla ileride tekrar açılabilir.

## Mevcut v9'dan yükseltme

1. Dosya ve veritabanı yedeği alın.
2. V9.1 dosyalarını mevcut proje dosyalarının üzerine yükleyin; `config/app.php` dosyanızı koruyun.
3. `database/migrations/2026-09-01-v91-home-ads-admin.sql` dosyasını **bir kez** çalıştırın.
4. `/admin/giris` üzerinden ayrı yönetici hesabıyla giriş yapın.
5. `/admin/reklamlar` içindeki Teslimat Testi ile `desktop/mobile + il + ilçe` kombinasyonlarını doğrulayın.
6. Normal `/giris` ekranında yönetici hesabının giriş yapamadığını ve normal kullanıcı oturumunun admin yetkisi kazanmadığını doğrulayın.
7. Yeni bir kullanıcı kaydedip e-posta doğrulaması beklemeden profil ekranına geçtiğini test edin.

Sıfır kurulumda yalnızca güncel `database/schema.sql` yeterlidir; v9.1 migration çalıştırılmaz.
