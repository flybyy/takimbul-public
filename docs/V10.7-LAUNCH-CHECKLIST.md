# TakımBul V10.7 — Canlıya Çıkış Checklisti

## 1. Yedek ve dosya koruması

- Canlı veritabanının tam yedeğini alın.
- Mevcut `config/app.php` dosyasını koruyun; release ZIP bu dosyayı içermez.
- Mevcut `public/uploads/` kullanıcı dosyalarını silmeyin veya üzerine boş klasör kopyalamayın.
- `storage/logs` ve upload dizinlerinin web sunucusu tarafından yazılabilir olduğunu doğrulayın.

## 2. Dosyaları yükleyin

V10.7 uygulama dosyalarını mevcut uygulamanın üzerine yükleyin; canlı `config/app.php` ve kullanıcı uploadlarını koruyun.

Bu sürümün migration referansı:

`database/migrations/2026-09-05-v107-verification-roles-sponsored-news.sql`

Migration additive ve non-destructive tasarlanmıştır. Production repair aynı hedef şemayı idempotent olarak uygular.

## 3. Production repair

Önce dry-run/audit:

```bash
php scripts/production-repair.php
```

Çıktıyı kontrol ettikten sonra:

```bash
php scripts/production-repair.php --apply
```

Ardından tekrar audit çalıştırın:

```bash
php scripts/production-repair.php
```

Eksik tablo/kolon/index kalmamalı. Repair'i ikinci kez çalıştırmak mevcut `writer` veya `authorized` hesapları `super_admin` rolüne yükseltmemelidir.

## 4. Launch gate

```bash
php scripts/launch-check.php
```

V10.7 migration dosyası, kritik tablolar/kolonlar ve temel production gereksinimleri PASS olmalı.

## 5. Veritabanı write smoke

```bash
php scripts/production-smoke.php
```

Sponsor, Audit ve haber sponsor alanlarını içeren rollback-safe write smoke PASS olmalı.

## 6. Rol kabul testi

Süper Yönetici hesabıyla `/admin/ekip` ekranını açın.

1. Bir test **Yazar** hesabı oluşturun.
2. Bir test **Yetkili** hesabı oluşturun.
3. Yazarla giriş yapın:
   - yalnız Panel + Haberler görünmeli,
   - kendi haberini oluşturup düzenleyebilmeli,
   - başka yazarın haber düzenleme URL'si 403 vermeli,
   - Kullanıcılar, Audit, Reklamlar, Ayarlar ve Ekip erişimi 403 olmalı.
4. Yetkiliyle giriş yapın:
   - Haber, Sponsor, Kullanıcı/Moderasyon, Mavi Tik ve Audit erişimi çalışmalı,
   - Reklamlar, Ayarlar ve Ekip erişimi 403 olmalı.
5. Süper Yönetici tüm alanlara erişebilmeli.
6. **Son aktif Süper Yönetici** hesabını pasife alma veya rolünü düşürme denemesi reddedilmeli.

## 7. Mavi Tik kabul testi

1. Bir gerçek/test oyuncu hesabını admin kullanıcı detayından açın.
2. Mavi Tik verin.
3. Public oyuncu profili, oyuncu listesi, arama ve takım kadrosunda küçük mavi rozet görünmeli.
4. Public HTML içinde oyuncunun gizli telefon/e-posta bilgisi yalnız tik verildi diye açığa çıkmamalı.
5. Tiki kaldırın ve public rozetin kaybolduğunu doğrulayın.
6. Audit Log'da `player.verification_granted` ve `player.verification_revoked` kayıtlarını kontrol edin.

## 8. Sponsorlu haber kabul testi

1. Yetkili/Süper Yönetici ile bir Haber Sponsoru oluşturun.
2. Yazar hesabıyla yeni haber oluşturup bu aktif sponsoru seçin.
3. Haberi yayınlayın.
4. Public haber kartında Sponsorlu etiketi, detay sayfasında **SPONSORLU İÇERİK** açıklaması görünmeli.
5. Sponsor CTA'sında `rel="sponsored noopener noreferrer"` bulunmalı.
6. Sponsoru pasif yapın; eski yayın public olarak bozulmamalı fakat yeni haberde seçilememeli.
7. `/yazar/{slug}` yazar profili ve haber byline'ı doğru görünmeli.

## 9. Audit kabul testi

Yetkili veya Süper Yönetici ile `/admin/audit` sayfasını açın. Mavi Tik, rol değişikliği ve sponsorlu haber işlemleri görünmeli. Şifre, password hash, session/token, telefon veya e-posta Audit metadata'sında bulunmamalı.
