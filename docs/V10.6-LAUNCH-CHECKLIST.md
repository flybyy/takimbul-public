# TakımBul V10.6 — Canlıya Çıkış Checklisti

## 1. Yedek

Canlı dosyalar ve MySQL veritabanının tam yedeğini al. Özellikle aşağıdaki tabloları ayrıca doğrula:

- `users`
- `teams`
- `team_members`
- `matches`
- `transfer_offers`

## 2. Dosyaları yükle

V10.6 production ZIP içeriğini uygulama köküne yükle.

Aşağıdakilerin üzerine yazma/silme:

- `config/app.php`
- mevcut `public/uploads/` kullanıcı dosyaları
- canlıya özel sunucu konfigürasyonu

## 3. PHP/MySQL gereksinimi

```bash
php -v
php -m | grep -i pdo_mysql
```

PHP 8.1+ ve `pdo_mysql` aktif olmalı.

## 4. Repair dry-run

```bash
php scripts/production-repair.php
```

Çıktıyı incele. Veri silen DROP/TRUNCATE beklenmez.

## 5. V10.6 şemasını uygula

```bash
php scripts/production-repair.php --apply
```

Bu adım mevcut veriyi koruyarak eksik V10.6 kulüp/kadro alanlarını ve `team_formations` tablosunu tamamlamalıdır.

## 6. Launch check

```bash
php scripts/launch-check.php
```

Özellikle şu satırlar PASS olmalı:

- V10.6 club squad migration
- DB bağlantısı
- Zorunlu DB tabloları
- Zorunlu DB kolonları
- DB runtime şeması
- Production repair scripti
- Production smoke scripti

## 7. Transactional production smoke

```bash
php scripts/production-smoke.php
```

Çıktıda geçici kulüp/kadro/diziliş yazımının başarılı olduğu ve verilerin rollback edildiği görülmeli.

## 8. Gerçek kullanıcı kabul testi

Canlıda iki test kullanıcısı ve iki test takımıyla doğrula:

1. Oyuncu A, Takım 1'e katılsın.
2. Oyuncu A, Takım 2 teklifini de kabul etsin.
3. Oyuncunun Takım 1 üyeliğinin hâlâ aktif olduğunu doğrula.
4. Takım 1 ve Takım 2'de farklı forma numarası/mevki/statü kaydet.
5. Oyuncu dosyasında iki takımın da ayrı ayrı göründüğünü doğrula.
6. Kaptan yönetiminden 7v7 diziliş kaydet.
7. Public takım sayfasında saha dizilişinin doğru oyuncularla göründüğünü doğrula.
8. Doğrulanmış maç verisi olan oyuncunun kartında TakımBul Form puanı; verisi olmayan oyuncuda `Yeni Oyuncu` göründüğünü doğrula.
9. Aynı takımda dolu forma numarası verildiğinde sistemin duplicate jersey'i engellediğini doğrula.
10. Transfer teklifindeki forma numarası sonradan dolarsa transferin yine kabul edilip uyarı verdiğini doğrula.

## 9. Public/gizlilik kontrolü

- Takım public profilinin HTML kaynağında oyuncu telefon/e-posta bilgisi bulunmamalı.
- Kayıt ekranında gerçek kullanıcı adı veya gerçek telefon numarası placeholder olarak görünmemeli.
- `/takim/{id}/yonet` yalnız takım kaptanına açık olmalı.
- Dizilişe başka takımın oyuncu ID'si elle POST edilince istek reddedilmeli.

## 10. SEO kontrolü

Bir public takım sayfasında:

- title: `Takım Adı Kadrosu, Oyuncuları ve Maçları | TakımBul`
- canonical
- meta description
- SportsTeam JSON-LD
- OpenGraph

kaynak kodda görünmeli.

## 11. Son görsel kontrol

En az:

- 360 px telefon
- 430 px telefon
- 768 px tablet
- 1366 px desktop
- 1920 px geniş desktop

üzerinde takım profili, kadro kartları, diziliş ve takım yönetimini kontrol et. Yatay scroll, dev SVG ok, kart çakışması veya saha dışına taşan slot olmamalı.

- repair PASS

- public gizlilik kontrolü PASS
- mobil/desktop görsel kabul PASS
