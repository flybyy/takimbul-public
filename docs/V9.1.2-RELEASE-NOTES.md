# TakımBul V9.1.2 — Final Launch Hardening

V9.1.2, kullanıcı kayıtları açılmadan önce yapılan son stabilizasyon ve üretim sertleştirme sürümüdür. Yeni ürün özelliği eklemek yerine kayıt/giriş sürekliliği, oturum güvenliği, hata yüzeyleri, route/view bütünlüğü ve canlı kurulum ön kontrolleri güçlendirilmiştir.

## Kayıt ve giriş güvenilirliği

- Üye kaydı artık `users` + `player_profiles` oluşturmayı tek veritabanı transaction'ında yapar.
- Profil kaydı başarısız olursa yarım kullanıcı hesabı bırakılmaz; işlem rollback edilir.
- Gerçek duplicate e-posta hatası ile veritabanı/altyapı hataları birbirinden ayrılır.
- Altyapı hatasında kullanıcıya yanlış "e-posta zaten kayıtlı" mesajı gösterilmez; HTTP 503 ile kontrollü kayıt formu hatası gösterilir ve hata loglanır.
- E-posta doğrulaması kapalıyken yeni üye güvenli biçimde doğrudan oturum açar ve profil düzenlemeye yönlendirilir.
- `/kariyer/vitrin` ve `/rakip-bul/anlik` korumalı GET akışlarının session başlangıcı garanti altına alınmıştır.

## Ayrı admin sınırı

- `veribayt` ve `admin@takimbul.com.tr` kimlikleri veritabanı geçici olarak erişilemez olsa bile normal kullanıcı kaydında rezerve kabul edilir.
- Admin oyuncu/kullanıcı değildir; admin oturumu ile public kullanıcı oturumu ayrımı V9.1 mimarisindeki gibi korunur.

## Profesyonel hata ekranları

- 403, 404 ve 419 yanıtları tek TakımBul tasarım diline alındı.
- CSRF süresi dolduğunda boş ekran yerine doğru HTTP 419 sayfası görünür.
- Yetkisiz takım/maç/scout işlemlerinde düz metin yerine HTTP 403 ekranı görünür.
- Bulunamayan kaynaklarda düz metin yerine HTTP 404 ekranı görünür.
- Production 500 ekranı teknik ayrıntı sızdırmadan kalır; gerçek hata `storage/logs` altında kayda alınır.

## Launch-check güçlendirmesi

`scripts/launch-check.php` artık canlı açılıştan önce şunları kontrol eder:

- PHP 8.1+
- `pdo_mysql`
- production config ve HTTPS URL
- debug kapalı olması
- log ve avatar klasörlerinin yazılabilir olması
- front controller
- CSS ve JS dosya bütünlüğü
- giriş, kayıt, 403, 404, 419 ve 500 kritik view dosyaları
- bütün aktif TakımBul tabloları
- kritik DB kolonları
- ayrı `veribayt` admin hesabı
- e-posta doğrulamasının geçici kapalı durumu
- v9/v9.1 kritik route ve migration dosyaları
- eski `Auth::isAdmin()` regresyonunun geri gelmemesi

Kritik `[!!]` satırı varken kullanıcı kayıtlarını açmayın.

## Otomatik bütünlük testleri

V9.1.2 ile eklenen testler route tanımlarını controller sınıf/metotlarıyla karşılaştırır, POST route'larında CSRF kontrolünü doğrular, literal view referanslarının gerçekten var olduğunu kontrol eder ve kullanıcıya dönük 403/404/419 yanıtlarının boş/düz metin olmamasını güvence altına alır.

## Veritabanı

**V9.1.2 için yeni migration yoktur.**

- V9.1 migrationı (`database/migrations/2026-09-01-v91-home-ads-admin.sql`) daha önce çalıştıysa tekrar çalıştırmayın.
- Mevcut kurulumda `database/schema.sql` çalıştırmayın ve veritabanını sıfırlamayın.
- V9.1 migrationı hiç çalışmadıysa onu yalnızca bir kez çalıştırın.

## Mevcut siteyi yükseltme

1. `config/app.php` dosyanızın yedeğini alın ve yeni paketle ezmeyin.
2. `public/uploads/` içindeki kullanıcı dosyalarını koruyun.
3. V9.1.2 uygulama dosyalarını yükleyin.
4. V9.1 migrationı daha önce çalıştıysa yeni SQL çalıştırmayın.
5. Sunucuda `php scripts/launch-check.php` çalıştırın.
6. Kritik `[!!]` kalmadığını doğrulayın.
7. `/assets/css/app.css` ve `/assets/js/app.js` adreslerinin HTTP 200 döndüğünü kontrol edin.
8. Kayıt → profil düzenleme → çıkış → tekrar giriş akışını gerçek test hesabıyla doğrulayın.
9. Ayrı `/admin/giris` hesabını ve `/admin/reklamlar` teslimat testini doğrulayın.
10. Bundan sonra kullanıcı kayıtlarını açın.
